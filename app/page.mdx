<Section icon="💡" title="How it works" time="30-second read">

Keploy sits next to your app and watches its traffic. **Record** once against the real database, then **replay**
as often as you like without it.

<RecordReplayDiagram />

<Details title="Why is this better than writing integration tests?">

Your tests exercise real HTTP, real handlers and real driver code, yet they run like unit tests: Keploy answers the
database queries from recorded mocks, so CI doesn't need a Mongo container. And because Keploy hooks into the
network layer (eBPF on Linux), you don't add an SDK or change your code.

</Details>

</Section>

<Section n={1} title="Install Keploy" time="1 minute">

```bash
curl --silent -O -L https://keploy.io/install.sh && source install.sh
keploy --help
```

If you see a list of commands including `record` and `test`, you're set.

<Section n={2} title="Get the sample app" time="1 minute">

```bash
git clone https://github.com/keploy/samples-go.git
cd samples-go/gin-mongo
rm -rf keploy   # start clean
```

The last line removes the repo's pre-recorded tests. The app is a URL shortener: `POST /url` stores a link in Mongo,
`GET /:id` redirects to it.

├── docker-compose.yaml   # app (ginMongoApp) + mongo
└── keploy/               # pre-recorded tests (you just deleted these)
`}
</FileTree>

<Section n={3} title="Record some tests" time="5 minutes">

Start the app **through** Keploy. Pick how you run it:

<Tabs labels={["Docker Compose", "Native (go run)"]}>
<Tab>

```bash
docker network create keploy-network   # the compose file expects it
keploy record -c "docker compose up" --container-name "ginMongoApp"
```

`--container-name` tells Keploy which container is your app.

</Tab>
<Tab>

```bash
docker compose up mongo
```

In `main.go`, point the app at `localhost`, then record:

```go title="main.go" {1}
client, err := New("localhost:27017", dbName) // was "mongoDb:27017"
```

```bash
keploy record -c "go run main.go handler.go"
```

</Tab>
</Tabs>

Once Gin says `Listening and serving HTTP on :8080`, open another terminal and use the app:

```bash
curl -X POST localhost:8080/url   -H 'content-type: application/json' -d '{"url": "https://google.com"}'
curl localhost:8080/Lhr4BWAi
```

Each call shows up in Keploy as a captured test. Stop with <kbd>Ctrl</kbd> + <kbd>C</kbd>.

<Details title="Why is the short ID always Lhr4BWAi?">

The app derives it from a SHA-256 hash of the long URL, so `https://google.com` always becomes `Lhr4BWAi`. That
determinism is why the recorded `GET` keeps passing on replay.

</Details>

<Details title="Permission denied on Linux?">

Keploy needs root to attach its eBPF hooks. Run it with `sudo -E env PATH=$PATH keploy record ...` so `sudo` still
finds Go and Docker.

</Details>

</Section>

<Section n={4} title="See what Keploy wrote" time="2 minutes">

<FileTree>
{`
keploy/test-set-0/
├── tests/
│   ├── test-1.yaml   # POST /url
│   └── test-2.yaml   # GET /Lhr4BWAi
└── mocks.yaml        # every Mongo query + its reply
`}
</FileTree>

Each test is plain YAML: the request, the response, and a **noise** list.

```yaml title="tests/test-1.yaml (trimmed)" {7-10}
req:
  method: POST
  url: http://localhost:8080/url
resp:
  status_code: 200
  body: '{"ts":1718943885198315028,"url":"http://localhost:8080/Lhr4BWAi"}'
assertions:
  noise:
    body.ts: []
    header.Date: []
```

<Callout type="aha" title="Noise = fields that change every run">
  `ts` is a timestamp, so Keploy ignores it when comparing. Add your own changing fields (UUIDs, `createdAt`) the
  same way.
</Callout>

<Callout type="tip">Commit the `keploy/` folder. It *is* your test suite.</Callout>

</Section>

<Section n={5} title="Replay them" time="2 minutes">

<Tabs labels={["Docker Compose", "Native (go run)"]}>
<Tab>



You should see **2 passed, 0 failed**. `--delay 10` gives the app time to boot; raise it if the first test can't
connect.

<Details title="Try it: replay with MongoDB switched off">

On the native path, run `docker stop mongoDB` and replay again. The tests still pass: every Mongo query was
answered from `mocks.yaml`.

</Details>

</Section>

<Section n={6} title="Break it on purpose" time="3 minutes">

Rename a field in the `POST /url` response in `handler.go`:

```go title="handler.go" {3}
c.JSON(http.StatusOK, gin.H{
	"ts":        time.Now().UnixNano(),
	"short_url": "http://localhost:8080/" + id, // was "url"
})
```

Run `keploy test` again (Compose users: add `--build` to the compose command). **test-1 fails** with a diff showing
`url` missing. Any client reading `url` would have broken, and you caught it without writing an assertion.

<Details title="What if the change was intentional?">

Delete the stale test (or the whole test set) and record again. Re-recording is how you update Keploy tests; don't
hand-edit the YAML.

</Details>

</Section>

<Section icon="🛟" title="Stuck?" time="Common problems">

<Details title="“network keploy-network declared as external, but could not be found”">

Run `docker network create keploy-network`, then record again.

</Details>

<Details title="The app can't reach Mongo when using go run">

The host is still `mongoDb`. Change it to `localhost:27017` in `main.go`.

</Details>

<Details title="The first test fails with “connection refused”">

The app wasn't ready when replay started. Increase `--delay`.

</Details>

<Details title="My code change has no effect in Compose mode">

Compose reused the old image. Use `-c "docker compose up --build"`.

</Details>
